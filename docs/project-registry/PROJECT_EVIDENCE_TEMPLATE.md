## Reproduce the Demonstration

Record dependency/runtime versions, install commands, minimal fixtures, invocation,
expected observable result, file writes and external downloads. Mark paid/network
paths explicitly. Do not place credentials in commands, fixtures, screenshots or
documentation. Give an offline path only when it actually avoids downloads.

Separate fixture contracts, model evaluation, API integration, frontend tests,
container builds and live service health. Bind each result to its actual revision.

## Data and Provenance

State public/synthetic/restricted data mode, source attribution, permitted reuse,
dataset and preprocessing hashes, and report/model identities where available.
Do not copy CVs, contacts, application histories or private operational data.

## Deployment Evidence

Provide a dated public smoke receipt only after checking actual responses.
Source publication, preview success and deployed API readiness are different facts.

## Limitations and Next Work

List observed gaps, uncertainty and bounded next improvements. Avoid fabricated
scores, unsupported performance claims or unverified production-readiness language.

## Career Claim Review

Approved CV claims: none unless a separate, exact approval receipt exists.
Technical source evidence can be recorded without approving its use as a CV claim.
